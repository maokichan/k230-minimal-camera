# 决策：仓库治理方案 —— cross-patch 机制、TuRead 的 Node 实现、无 identity 门控

Status: implemented

## Problem

新仓库需要一套针对 agent 的项目管理机制（文档门禁、决策记录等），总体参照 cross-patch 的方案；但 cross-patch 的守卫脚本是 Python，本仓库技术路线不走 Python。

## Decision

- 机制口径整体参照 cross-patch：AGENTS.md 子树分治、三守卫 pre-commit 门控链、.agents/notes 决策笔记（路径即元数据、三态生命周期）、行数门禁、trash/ 可恢复删除。
- 守卫脚本用零依赖 Node ESM 实现（`ops/scripts/<域><动作>.mjs`），实现参照 TuRead 的同名三守卫移植。
- **不设 identity/Worked-by 溯源门控**：提交身份由 git 自带（user.name/email）承担。

## Alternatives considered

- 直接复用 cross-patch 的 Python 守卫：与本仓库"不走 Python"的技术路线冲突，为四个脚本养第二套运行时不值。
- 连 identity 门控一起用 Node 重写：git 本身已承载提交身份，二次溯源是重复记账，还徒增各机器 init 密钥的仪式。

## Consequences

- 守卫语义与 cross-patch/TuRead 一致，跨仓库经验直接迁移。
- 无 Worked-by 尾注：溯源退化为 git log 的 author 信息，接受。
