# 决策：固件技术路线走 CanMV（MicroPython），Node 只用于仓库治理

Status: implemented

## Problem

极简相机在 K230 上怎么写：CanMV（MicroPython）、K230 Linux SDK（C）还是裸机？仓库治理脚本的语言栈选什么？

## Decision

- 板端固件走 **CanMV（MicroPython）**：庐山派出厂支持、官方 AI 例程与 API 手册齐全、拍照存卡链路最短。
- 仓库治理与工具脚本走 **Node（零依赖 ESM .mjs）**，参照 TuRead 移植三守卫；不引入 Python 工具链。

## Alternatives considered

- K230 Linux SDK + C：能力上限高（真 Linux 环境），但相机链路要自己打通 VICAP/VENC，与"极简"目标相反，且偏离庐山派的官方支持面。
- 板端跑 JavaScript 运行时：K230 没有官方 JS 运行时或移植，风险全在自己身上；JS/TS 的位置在宿主机治理层，不在板端。

## Consequences

- 板端代码 = MicroPython 单文件起步，受 CanMV 固件能力边界约束（事实归属 docs/research/ 调研文档）。
- 仓库内并存两种运行时（板端 MicroPython / 宿主 Node），域规则分属 src/ 与 ops/ 的 AGENTS.md。
- 后续：Rust 挂载点与两步走计划见 [2026-11-07-Rust挂载点与两步走.md](2026-11-07-Rust挂载点与两步走.md)。
